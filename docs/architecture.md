# Архитектура проекта «Чичик»

## 1. Описание продукта

**Чичик** — веб-приложение для подготовки ученика к ОГЭ и ЕГЭ.

| Параметр | Значение |
|----------|----------|
| Аудитория | Ученик (один пользователь, без классов и учителей) |
| Админ | Редакторы контента (роль `admin`, несколько человек) |
| Профили | ОГЭ и ЕГЭ в одном аккаунте |
| Предметы MVP | Русский язык, математика (базовая), обществознание, химия |
| Контент | Оболочка: 5 тем на предмет, 5–8 заданий на тему, ≥1 пробник на предмет |
| Питомец | UI-фича (дельфин Чичик, чирики, магазин еды) — не блокирует учебный MVP |
| Стиль UI | Спокойный учебный edtech; питомец — отдельный раздел, не «детский» комикс |
| Критерий готовности MVP | Регистрация + темы с теорией/практикой + диагностика + банк ошибок + пробники + админка контента |

### Must-have v1

1. Регистрация и вход (ученик)
2. Выбор профилей ОГЭ / ЕГЭ и предметов
3. Теория и практика по темам
4. Диагностика слабых тем
5. Банк ошибок
6. Пробные варианты (на время)
7. Админ-панель: предметы, темы, задания, пробники, тексты лендинга
8. Питомец (картинка + чирики + магазин) на mock/localStorage до отдельной синхронизации с БД

### Вне scope v1

- Кабинет учителя / группы / классы
- ИИ-проверка сочинений
- Рейтинги и соцсеть
- Мобильное нативное приложение
- Персональный недельный план (кандидат на v2)
- Биология и география как учебные предметы MVP (можно вернуть позже)
- Черновики контента (`is_published`) — в MVP сохранил = сразу видно ученику

## 2. Высокоуровневая схема

```text
┌──────────────────────────────────────────────────┐
│  Browser                                         │
│  ├── Ученик  → /app/**                           │
│  └── Админ   → /admin/**                         │
└─────────────────────┬────────────────────────────┘
                      │ HTTPS
                      ▼
┌──────────────────────────────────────────────────┐
│  Vercel — Next.js (App Router)                   │
│  Server Components / Server Actions              │
│  Проверка role на сервере для /admin             │
└─────────────────────┬────────────────────────────┘
                      │ Supabase JS (user session)
                      ▼
┌──────────────────────────────────────────────────┐
│  Supabase Free                                   │
│  ├── Auth (email/password)                       │
│  ├── PostgreSQL + RLS                            │
│  └── (Storage позже, при необходимости)          │
└──────────────────────────────────────────────────┘
```

Контент хранится в PostgreSQL. Стартовый набор — seed; дальше правки через админку.  
Service role key — только на сервере / в CI для миграций и seed, никогда в браузере.

## 4. Роли и доступ

### 4.1. Роли

| Роль | Назначение | Назначение в системе |
|------|------------|----------------------|
| `student` | Ученик | По умолчанию при регистрации |
| `admin` | Редактор контента | Несколько человек; назначается через `ADMIN_EMAILS` |

`profiles.role`: `'student' | 'admin'`, default `'student'`.

### 4.2. Назначение админа

1. В `.env` / `.env.local` / Vercel: `ADMIN_EMAILS=admin1@example.com,admin2@example.com`
2. При регистрации или первом входе: если email в списке → `profiles.role = 'admin'`
3. Дополнительно допустим ручной SQL в Supabase для починки.

Новые редакторы позже — добавить email в `ADMIN_EMAILS` (и при необходимости обновить уже существующий `profiles.role`).

### 4.3. Права

| Действие | student | admin |
|----------|---------|-------|
| Учёба, свой прогресс | да | да (как обычный пользователь) |
| Чтение учебного контента | да | да |
| CRUD предметов, тем, заданий, пробников | нет | да |
| Редактирование текстов лендинга | нет | да |
| Доступ к `/admin/**` | нет | да |
| Чужой прогресс / ответы учеников | нет | нет в MVP |

### 4.4. Безопасность админки

- Middleware + серверные проверки `role === 'admin'` на каждый Server Action админки
- RLS: write на таблицы контента только если `profiles.role = 'admin'`
- Ученик не может повысить себе роль через клиент
- Нет «скрытой кнопки» без серверной проверки

## 7. Модель данных (PostgreSQL)

### 7.1. Пользователи и настройки

```text
profiles
  id (uuid, = auth.users.id)
  display_name
  role                 -- 'student' | 'admin'
  created_at

user_exam_profiles
  user_id
  exam_type            -- 'oge' | 'ege'
  enabled

user_subjects
  user_id
  exam_type
  subject_code         -- 'russian' | 'math_basic' | 'social' | 'chemistry'
  enabled
```

### 7.2. Контент (правка админом; сразу публичный)

```text
subjects
  code                 -- PK
  title
  short_description
  sort_order
  exam_types           -- text[] или отдельная связь; ОГЭ/ЕГЭ
  -- без is_published в MVP

topics
  id
  subject_code
  exam_type
  title
  theory_md
  sort_order

tasks
  id
  topic_id
  task_type            -- single | multi | short | numeric
  stem
  options_json
  answer_key
  solution_md
  difficulty           -- 1..3
  sort_order

exams
  id
  subject_code
  exam_type
  title
  duration_min

exam_tasks
  exam_id
  task_id
  sort_order

site_content
  key                  -- например 'landing.hero_title'
  value_md             -- или value_text
  updated_at
  updated_by
```

### 7.3. Прогресс ученика

```text
attempts
  id, user_id, task_id, exam_attempt_id?, user_answer, is_correct, time_spent_sec, created_at

exam_attempts
  id, user_id, exam_id, started_at, finished_at, score_raw, score_max, weak_topics_json

topic_mastery
  user_id, topic_id, mastery, last_diagnosed_at, updated_at

error_bank
  id, user_id, task_id, times_wrong, resolved, next_review_at, updated_at
```

### 7.4. Питомец (MVP)

- Состояние питомца (чирики, сытость, инвентарь) — **localStorage** в v1 UI.
- Перенос в Postgres — отдельная задача после учебного ядра (не блокер MVP учёбы).

### 7.5. RLS

- `profiles` / `user_*` / `attempts` / `exam_attempts` / `topic_mastery` / `error_bank` — только свой `user_id`.
- `subjects`, `topics`, `tasks`, `exams`, `exam_tasks`, `site_content` — **SELECT** всем авторизованным (и публичный read для нужных ключей лендинга).
- **INSERT/UPDATE/DELETE** контента и `site_content` — только `auth.uid()` с `profiles.role = 'admin'`.
- Ученик не пишет в таблицы контента.

## 8. Ключевые сценарии

### 8.1. Регистрация и онбординг

1. Ученик создаёт аккаунт (email + пароль).
2. Создаётся `profiles` (`role=student`, либо `admin` если email в `ADMIN_EMAILS`).
3. Выбор ОГЭ/ЕГЭ и предметов из четырёх.
4. Переход на `/app`.

### 8.2. Теория → практика

1. Предмет → тема → теория (`theory_md`).
2. Решение 5–8 заданий, auto-check.
3. Разбор, `attempts`, mastery, при ошибке — `error_bank`.

### 8.3. Диагностика

1. Набор заданий на все 5 тем предмета.
2. Пересчёт mastery; карта слабо / средне / хорошо.

### 8.4. Банк ошибок / пробник

Без изменений логики относительно прежней версии: upsert ошибок; пробник с таймером без подсказок до финиша.

### 8.5. Работа админа

1. Вход тем же auth; доступ в `/admin`.
2. Создаёт/правит предмет, тему, задание, пробник, текст лендинга.
3. Сохранение сразу видно ученикам (без черновиков).

---

## 9. Логика обучения (MVP)

```text
mastery < 40  → слабо
40..69        → средне
>= 70         → хорошо
```

- Неверный ответ → upsert в `error_bank`
- Верный повтор из банка → `resolved = true`
- Диагностика покрывает все 5 тем
- Пробник: таймер, без подсказок до конца

| Требование | Цель MVP |
|------------|----------|
| Безопасность | RLS + серверная проверка admin; секреты в env |
| Производительность | Тема/задание < 2 с |
| Адаптив | Desktop + mobile (ученик); админка — desktop-first |
| Стоимость | Free Vercel + Supabase |

## 13. Риски

| Риск | Митигация |
|------|-----------|
| Утечка прав админа | Только server-side role check + RLS |
| Мало контента | Seed + админка для быстрого наполнения |
| Раздувание scope (био/гео) | Вне MVP; питомец не смешивать с каталогом предметов |
| Лимиты Free | Компактный контент, без тяжёлых файлов |
